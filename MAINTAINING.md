# WiiUNX2 maintainer handoff

## Purpose and boundaries

Independent Aroma-compatible Wii U menu, derived from launchiine. Horizontal software row, touch scrolling, users, search, sort, discs and homebrew. No Nintendo endorsement is implied. Source licenses do not establish legal clearance of the visual design. No console system files are to be modified.

The published checkout is self-contained. In the original development workspace, launcher/ and dependencies/ are working sources, github-upload/ is the publishing checkout, and dist/, input/, firmware dumps and usage logs are private. Do not copy the workspace wholesale. Old test ZIPs may contain Nintendo recordings and uncleared historical fonts. Never attach them as public release assets.

## Architecture and file map

- launcher/src/entry.cpp: process lifetime and opt-in local diagnostics; no UDP/module logging initialization.
- Application.cpp/.h: ProcUI foreground lifecycle, frame loop, shared-font preference, graphics teardown/recreation. Waits for GPU work before freeing resources.
- menu/MainWindow.cpp/.h: row/dock rendering, controls, dialogs, boot-time and manual account selection, background workers, native recent-history sorting and SD fallback history.
- menu/HomeGeometry.h and Library.h: host-testable navigation, selection preservation, search and keyboard geometry.
- game/GameList.cpp/.h: installed-title enumeration and metadata. Installed titles publish before the SD scan. A bounded process-memory cache reuses names when ID/path/reported version match. It does not survive process exit and never holds GPU objects. The persistent name cache lives at `wiiu/WiiUNX2/names.cache`; legacy root-level cache files and their `.bak`/`.tmp` sidecars are moved there at startup.
- game/Homebrew.cpp/.h: bounded recursive SD app scan, .ignore filtering, WUHB preference, RPX sidecar/WUHB bundle metadata and icons. Stable private-namespace IDs derive from paths. ID collisions are skipped. Bundle API work is serialized with a mutex. Homebrew display names reuse the persistent name cache only when the app and its metadata files' size, inode, modification time and change time still match; path discovery and visibility policy are re-evaluated every startup. Icons and runtime/plugin state are never cached.
- game/HomebrewPolicy.h: reads documented JSON flags from Homebrew on Menu's storage format. Active environment is queried through Mocha; normal aroma path is the fallback. Missing/malformed storage uses plugin defaults. It follows visibility settings, not whether the plugin is loaded.
- game/Metadata.h: bounded strings, XML titles and TGA validation.
- utils/AtomicHistory.h: temporary-file write, backup rotation, best-effort recovery. Host tests do not prove resilience to physical SD failure or arbitrary power loss.
- MenuMusic.cpp/.h: original background loop and bundled procedural UI effects (`ui*Default.bin`), with optional locally supplied overrides. Invalid or missing overrides fall back to bundled cues. Audio buffers/voices are released during foreground loss.
- resources/: generated asset table. Do not commit generated filelist.h.
- dependencies/libgui: modified renderer/font/image library; texture validation, UTF-8, rounded alpha and transparent-texel colour bleed (EdgeBleed.h, applied to RGBA8 textures during conversion) are part of the project and must ship as source.
- dependencies/librpxloader and libwuhbutils: official LGPL Aroma client libraries. Runtime modules come from the user's environment, not this source distribution.
- Wii U HTTPS: devkitPro `wiiu-curl` portlib (curl license) with Mbed TLS; install via `pacman -S wiiu-curl`. Peer and hostname verification are mandatory. `UpdateService.cpp` supplies the two observed GitHub trust anchors from `UpdateCaBundle.h`; review chain rotation and expiry before changing them. Wii U date/time and TLS behavior remain hardware checks.
- launcher/tools/: original image/music generators, optional audio importer, host checks and packaging commands.
- launcher/licenses/ and THIRD-PARTY.md: font licensing and dependency attribution. UPSTREAM-REVISIONS.txt records starting revisions.

## Lifecycle, threading and conventions

The render thread owns GUI/GPU resources. Workers return copied CPU metadata or validated bytes through queues/futures; GPU texture creation stays on the render thread. Join workers and wait for GPU completion before releasing graphics heaps. Never keep a menu object with stale texture/font pointers across foreground loss.

Applet return may preserve the process; games may exit/restart it. RAM caching can accelerate only the former. Re-enumeration remains necessary to check installed titles. GPU/font/icon recreation is intentional. Before a full title handoff, MainWindow stops and joins the MCP/title loader and waits for pending icon and play-history reads; do not launch while background IPC is still active. If ACT has no default account, WiiUNX2 asks who is using the console once per system boot. It stores only the boot-time marker in `wiiu/WiiUNX2/account-chosen.txt`, so a menu restart during the same boot does not ask again. A configured default account skips the prompt. The persistent name cache (`wiiu/WiiUNX2/names.cache`) is wired: GameList reads it lazily on the loader thread and MainWindow saves it right after the metadata pass. It stores title IDs, versions or homebrew file stamps, paths and display names, not installed games, icons or Aroma plugin state. It reuses the MetadataCache.h format and atomic writer. Installed titles are still enumerated on startup. Cached icons and other metadata are not wired and do not accelerate the installed-title scan; keep issue #4 open until hardware validation. Recent history and opt-in logs are also under `wiiu/WiiUNX2/`. On startup, legacy root-level WiiUNX2 files plus `.bak`/`.tmp` recovery sidecars are moved when the destination does not exist; conflicts preserve both files and keep using the organized copy. The required `men.rpx`, StyleMiiU plugin, and updater transaction files remain at their required/adjacent paths. MainWindow::saveView returns the selected title and rebuildView restores it until the user navigates. reconcile() (launcher/src/menu/Reconcile.h) is NOT wired: the window is recreated on foreground return, so it has nothing to diff.

Layout uses logical 1280x720 coordinates. The software row has 256-pixel tiles and a 272-pixel step; the dock has nine actions. Selected-tile outline pulse (launcher/src/gui/SelectionPulse.h, GameIcon.cpp): the cyan-to-blue outline RGB is scaled by a sine between 0.80 and 1.20 over a fixed 2800 ms period (amplitude and period are constants, not settings). The selected app border keeps one rounded-square geometry and crossfades between eight full-outline gradient frames, shifting cyan, purple and pink colors smoothly around the border over a 480-frame period. The 288-pixel source frames are drawn at 280 pixels, leaving roughly a 5-pixel gap around the 256-pixel tile; the smaller outer outline also gives more room to adjacent tiles. The selected account rectangle uses the same eight animated frames, scaled to its existing 156x172-pixel frame. The selected dock/profile gradient ring rotates at 0.75 degrees per menu frame. A Mii avatar is drawn over a solid white circular backing. The top-right network glyph currently indicates only connected/disconnected through `ACIsApplicationConnected`; the public [WUT Auto Connect API](https://github.com/devkitPro/wut/blob/master/include/nn/ac/ac_c.h) exposes no signal-strength field. However, WUT's [nsysnet import definition](https://github.com/devkitPro/wut/blob/master/cafe/nsysnet.def) lists `WDGetRssi`, `WDGetRadioLevel`, `WDScan` and `WDSortByRSSI`. These exports make a Wii U-native RSSI route plausible, but WUT headers provide no callable declarations and no public Wii U app usage was verified in this search. Signatures, initialization/context requirements, returned scale, whether values describe the associated access point or scan results, and effects on an active connection remain unknown; do not call these exports or display bars until reverse-engineered and hardware-tested. `CCRCDCGetWlanRSSIAnt` in [nsysccr](https://github.com/devkitPro/wut/blob/master/cafe/nsysccr.def) is a separate controller/CCR subsystem and is not evidence of the console's access-point RSSI. Host tests cover the pulse, color progression and source-frame gap; border rendering still needs console validation. The TV uses 1x AA without the TV-only FXAA post-process so small text remains unfiltered; this change needs console comparison against the DRC. TV output still uses less hardware AA than the DRC. TVii is a software-row entry with its native applet launch path. The disc tile uses a reserved ID and is revalidated before launch. Wii U discs use the existing path handoff; `MCP_APP_TYPE_GAME_WII` discs use a generic tile and request a system-managed `SYSLaunchTitle` handoff without applying Wii U title patches. The ODD detection, Wii-mode launch and return path all need console validation; see DISCS.md and issue #28. Current disc polling queries title information every two seconds after loading (backing off to 16 seconds after repeated errors); it is not proven to match stock Nintendo timing.

Default sort is recent. Native PDM statistics give last-played days for the active user, not exact same-day order. Locally dated launch requests break ties and cover homebrew; they do not prove a game actually ran. Local history is stored separately as `wiiu/WiiUNX2/recent-<ACT slot>.txt`; the number is the active account slot, not a game number. A file is created or updated when a launch request is recorded for that account; other slots may have no file, and existing files persist. Switching users reads that user's file and resets local/native history state. The row starts leftmost until the first navigation gesture; later metadata arrivals preserve the chosen title.

## Build and development

Install devkitPro's Wii U toolchain and required portlibs for FreeType/HarfBuzz/GD/PNG/JPEG/zlib/libmad/Tremor/Ogg/bzip2/Brotli. On Windows use launcher/Build.ps1; -DevkitPro selects its installation. Else build dependencies/libgui, dependencies/librpxloader, dependencies/libwuhbutils with make, then launcher. See the Makefiles for authoritative linker requirements. Generic tool installation defaults are configurable and are not private user paths.

Noto Sans Regular is a pinned unmodified OFL fallback; the console's shared font remains preferred. Preserve the font hash/license in THIRD-PARTY.md. Original procedural music is included. Optional user-provided effects require the user's own rights; the importer grants none. See SOUNDS.md.

Release version: set `WIIUNX2_VERSION` in `launcher/src/common/common.h` in the release commit. The pause menu and `launcher/tools/Package-Release.mjs` read that single define (`Package.ps1` forwards to it); `launcher/Update-SD.ps1` prints no version. `launcher/tests/version.mjs` fails if any of these reintroduce a hardcoded version. Release packages contain `WiiUNX2-menu-v<version>.zip` plus standalone `men.rpx` and checksum assets; upload all four outputs to the GitHub release. Existing git tags mix `v`-prefixed and bare names, so check the tag you create.

Run the commands in HOST-VALIDATION.md before compiling in the publishing checkout. The publication checker rejects generated artifacts; build a separate copy for cross-compilation. The manual source-validation workflow checks source exclusions, host tests and source archive creation. It has read-only permissions and does not deploy or publish binaries. Its checkout must include full reachable history for the history audit.

Do not use the old Dockerfile toolchain as a verified recipe: it predates current dependencies. Release packages are built only by `launcher/tools/Package-Release.mjs`; see the Release packaging section in HOST-VALIDATION.md. Validate distribution layout/recovery separately before recommending installation. Installation belongs on SD in the selected Aroma environment with backups; never overwrite NAND menu titles.

## Troubleshooting and remaining work

For private diagnostics create an empty `wiiu/WiiUNX2/debug.enabled` on SD and restart the menu. Remove it and restart to stop custom diagnostics. Logs can contain title IDs and profile slots. Check the direct SD app count and loader status if apps are absent; check Hide all homebrew, hideAllRPX, WUHB preference and wiiu/apps/.ignore. Not every legacy RPX is Aroma-compatible. Confirm normal RPXLoader/WUHBUtils runtime modules remain installed.

When returning from an applet, compare first-title and total-metadata timings against first load. Test cold boots, title launch/return, disc swaps, search/sort/touch, user changes and recent history through reboot. Do not deliberately interrupt power during a write. Prioritize observed failures and measured bottlenecks over speculative optimizations.

Next: wire and hardware-validate persistent metadata if pursued; investigate the title-launch hangs; test keyboard repeat, optional sound cues, icon loading, disc removal/swaps, privacy defaults, fallback font, installer and recovery. Overall legal clearance, exhaustive security testing, plugin compatibility and 1.0 readiness are not established.

## Launch hang diagnostics (issue #17)

Issue #17 reports that some installed titles hang at the Wii U logo. A prior v0.7.3 path-based experiment was reverted after it prevented regular games from launching. WiiUNX2 now stops its MCP/title loader and pending readers before full-title handoff, matching Launchiine's teardown; regular titles use `_SYSLaunchTitleWithStdArgsInNoSplash`, also matching Launchiine. These changes address a concrete background-IPC risk but are not proof of the StyleMiiU-specific failure's cause. The user reports that Launchiine exhibits similar failures through StyleMiiU RPX, while direct Aroma `men.rpx` replacement works. The attached Launchiine files contain caches but no UDP launch log, so the wrapper's title-specific hang remains unresolved. Do not include raw title IDs or usage data in public issue details.

Enable: create an empty file `wiiu/WiiUNX2/launch-log.enable` on the SD card. Delete it to stop logging. Nothing is written while it is absent.

What is recorded: one line per launch from WiiUNX2 in `wiiu/WiiUNX2/launch.log`, written just before the launch call. Each line holds the title ID, stage (`regular`, `regular-returned`, `disc`, `wii-disc`, `wii-disc-returned`, `homebrew-custom`), app type, and the title patch result (`not-called` on the Wii-disc and custom paths), then the title's storage path. `regular-returned` and `wii-disc-returned` are written only if the corresponding void launch API returns to WiiUNX2; neither provides a result code. A successful handoff exits this process, while a crash after handoff still leaves only the pre-call record. The path keeps only `A-Z a-z 0-9 / _ . -` (other characters become `?`) and is cut at 96 characters. The file is truncated before the next write once it passes 64 KiB. It stays on the SD card and is never sent anywhere. Each line contains only these fields. The 2026-11-19 report had 13 `regular` entries with `MCP_APP_TYPE_GAME` and patch result 0; title IDs and paths remain in the user's local log and are not reproduced here.

To attach it to the issue: check the file first, then paste its contents or attach it as text. Each line should start with `launch `. Remove any line you do not want to share.

Reporter checklist (please note each answer in the issue):
- Launch the same title from the stock Wii U menu, not from WiiUNX2. Does it hang there too?
- Repeat each launch 3 times, from WiiUNX2 and from the stock menu. Count the hangs.
- List the Aroma plugins installed.
- Storage: USB, internal MLC, or disc.
- Whether the title has an update or DLC installed.

The existing `wiiu/WiiUNX2/debug.enabled` diagnostics are separate; this marker does not enable them.

## Icon loading

menu/IconPlan.h decides which tile icons stay resident and in what order they load: the on-screen cards of the current and target scroll position plus a directional prefetch window (6 ahead, 2 behind, 2 each way at rest), capped at 20 resident, with on-screen cards never dropped. MainWindow::loadVisibleIcons applies it; one read stays in flight and one texture is uploaded per frame. The margins and cap are unmeasured defaults; tune them on hardware. launcher/tests/icon-plan.cpp covers the rules and a frame model of the loader (a model, not a hardware measurement).
## In-app updater (issue #7)

- `launcher/src/utils/UpdateCore.h` is pure release-policy and checksum logic; `UpdateService.cpp` owns HTTPS, bounded downloads, RPX validation, SD staging and installation. The updater downloads only the standalone `men.rpx` and `men.rpx.sha256` assets; it does not download or unpack the release ZIP.
- `MainWindow` asks before checking and asks again before installation. HTTPS peer/hostname checks are mandatory, redirects are disabled for the pinned API URL and manually validated for asset downloads, all transfers are size/time bounded, both GitHub asset digests must match, and the sidecar checksum must name and match the RPX.
- During installation the modal shows the RPX download byte progress and percentage. Checksum verification and the backup/install transaction are reported as separate phases because those file operations do not expose a reliable percentage.
- Installation is permitted only when `/dev/mcp` confirms the active environment is exactly `fs:/vol/external01/wiiu/environments/aroma`. RPXLoadingModule API v2+ identifies a running theme executable under `wiiu/themes/`; otherwise the updater falls back only to an existing regular `wiiu/environments/aroma/men.rpx`. A known but unsupported running path fails closed rather than falling back to another copy. It stages the new RPX beside the selected file and publishes a verified timestamped backup before replacement; after a new backup is secured, older in-app backups for that target are pruned, while manual/PowerShell backups are left alone. It never edits the StyleMiiU `.wps` plugin, another module, config or cache file. If `rename()` cannot replace the existing RPX, the updater moves the old file aside, installs the staged file with a second rename, verifies it, and rolls back on failure. This fallback is not fully atomic: a power loss between the two renames may require manual recovery from the verified backup. Keep the console powered on and do not remove the SD card during installation. The app directs the user to restart after success.
- GitHub release assets are not cryptographically signed. HTTPS and matching GitHub digests/checksums provide transport integrity but not independent publisher authenticity; the confirmation UI explicitly discloses this. Do not describe this as a signed or supply-chain-authenticated update.
- `launcher/tests/update-core.cpp`, `launcher/tests/update-install.cpp` and `launcher/tests/update-target.cpp` cover host-side policy, checksum, hash, replacement fallback/rollback and target-resolution cases. They cannot establish Wii U TLS trust-store behavior, RPXLoadingModule path reporting, SD rename semantics, power-loss recovery or console runtime behavior; real hardware validation remains required before recommending unattended updates.
- The allowlisted redirect hosts (github.com, objects.githubusercontent.com, release-assets.githubusercontent.com and api.github.com) are based on observed GitHub behavior, not a stable GitHub contract. Any host/path change should fail closed until reviewed.
